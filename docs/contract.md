# Контракт первой интеграции (проект v1)

## Данные и расчёт

Учебный каталог `training-v1`. Строки ниже — вход, а не готовый рейтинг. Банк и карта каждой строки: «Учебный банк {ID}», «Карта {ID}». Категории: supermarkets = Супермаркеты, cafe = Кафе, fuel = АЗС. Для детерминированных тестов дата 2026-11-20 UTC, дата актуальности 2026-11-01, период [2026-11-01, 2027-11-01), нижняя граница включена. В приложении — текущая серверная дата UTC; если стенд запускается вне периода, подготовьте новую явно датированную версию, не отключайте проверку.

| cardId | categoryId | rateBps (100 = 1%) | limitKopecks | minAmountKopecks |
|---|---|---:|---:|---:|
| A | supermarkets | 1000 | 10000 | 1 |
| B | supermarkets | 600 | 30000 | 1 |
| C | supermarkets | 400 | 20000 | 1 |
| D | supermarkets | 200 | 10000 | 1 |
| D | cafe | 800 | 30000 | 10000 |

Сервер отбирает действующие условия по набору карт, категории и минимальной сумме. Для карты сначала применяет подходящее условие категории, затем общее условие `all`, если специального нет. Расчёт в копейках: `(amountKopecks * rateBps + 5000) // 10000`. Затем применяется ограничение по условию и, в личном режиме, сохранённый месячный остаток. Если начисления неизвестны, доступен полный заданный лимит. Карты сортируются по убыванию итогового кэшбэка, при равенстве — по возрастанию `cardId`. Топ — первые три позиции. Импорт делает upsert по ключу `(cardId, categoryId, validFrom)` и отклоняет пересекающиеся периоды одного правила. Можно добавить поля `bankName` и `cardName` для отображения в каталоге.

## HTTP (JSON)

`POST /api/recommendations`, тело: `{"categoryId":"supermarkets","amountKopecks":250000,"scope":"all"}`. `scope` принимает `all` и `mine`. Личные категории допустимы в `mine`. `catalogVersion` идентифицирует набор условий расчёта. Ответ 200: объект с `asOf` (ISO-дата), `catalogVersion`, `top3` и `allMatches` (массивы одинаково устроенных позиций). Пример одной позиции:

```json
{"cardId":"B","bankName":"Учебный банк B","cardName":"Карта B","categoryId":"supermarkets","cashbackKopecks":15000,"calculation":{"beforeLimitsKopecks":15000,"afterCategoryLimitKopecks":15000,"monthlyRemainingKopecks":null,"monthlyUsageKnown":false},"rateBps":600,"limitKopecks":30000,"limitApplied":false,"minAmountKopecks":1,"validFrom":"2026-11-01","validUntilExclusive":"2027-11-01","updatedOn":"2026-11-01"}
```

При нулевой сумме: 422, `{"field":"amountKopecks","code":"positive_integer_required"}`. Пустая известная категория — 200 и два пустых массива. Неизвестная категория — 422 с полем categoryId. Ошибка сервера не равна пустому результату. Рубли форматирует UI, второй калькулятор на клиенте не нужен.

## Карты пользователя и покупки

`GET /api/cards?categoryId=…` — каталог с действующими условиями; `GET /api/cards/{id}` — подробности. `GET /api/me/cards` — сохранённые ID; `PUT`/`DELETE /api/me/cards/{id}` — идемпотентное добавление/удаление. При добавлении проверять существование карты. Привязка к непрозрачной cookie сессии (HttpOnly, SameSite, Secure на HTTPS); связи с картами в серверной БД, уникальность пары сессия+карта. Не принимать пользовательский ID из тела для выбора чужого списка. При пустом `mine` не переходить на `all`.

`PATCH /api/me/manual-cards/{id}/rate` принимает `{"categoryId":"Такси","label":"Такси","rateBps":300}` и возвращает 204. Поле `label` относится к подтверждённой активной строке текущего месяца. Для старой ручной категории без подписи используется `null`. Изменение ставки сохраняет период, остальные правила и ввод месячных начислений.

`GET /api/me/cards/{id}/monthly` возвращает `month`, `limitKopecks`, `usedKopecks` и `remainingKopecks`. `PUT` принимает оба поля `limitKopecks` и `usedKopecks`. Значение `null` означает, что поле не задано. В новом месяце сохраняется лимит, а начисления считаются неизвестными. Публичный каталог личные настройки не учитывает.

`POST /api/me/purchases` принимает `categoryId`, `amountKopecks`, `chosenCardId` и необязательный `requestId`. Один ключ с теми же данными повторяет ответ. Другие данные с тем же ключом дают 409. Журнал содержит расчёт на момент записи, доступен через `GET /api/me/stats` и не списывает месячный остаток.

Для поддерживаемого банка в результате `scope: "mine"` есть `bankAccess` с полями `id`, `name` и `webUrl`. Адрес берётся из фиксированного справочника. Экспериментальные диплинки доступны на `/bank-link-test`.
